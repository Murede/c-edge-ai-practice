## 5. State Machines

Learned that a state machine uses the current state and an incoming event to determine whether a transition is legal and what the next state should be.

```text
Current State + Event
        |
        v
  State Machine
        |
        v
Legal transition?
     /     \
   Yes      No
    |        |
New state  Error
```

Discussed why a faulted motor must not transition directly to running from a normal start command.

## 6. States vs Events

Created separate concepts for:

- **State:** where the system currently is.
- **Event:** what just happened.

Examples:

```text
MOTOR_RUNNING = state
EVENT_STOP    = event
```

Events act as catalysts for state transitions.

## 7. Intermediate Physical States

Discussed why real motor controllers may require:

```text
IDLE -> STARTING -> RUNNING -> STOPPING -> IDLE
```

rather than treating physical changes as instantaneous.

## 9. Runtime vs Compile-Time Errors

Clarified:

- Compile-time errors are detected while GCC builds the program.
- Runtime errors/status conditions occur while the compiled program executes.
- Invalid motor transitions and null controller pointers are runtime conditions.

## 10. State-Machine Practice

Implemented a simplified state machine using:

```text
MOTOR_IDLE
MOTOR_RUNNING
MOTOR_FAULT
```

with:

```text
EVENT_START
EVENT_STOP
EVENT_FAULT
EVENT_RESET
```

Legal transitions:

```text
IDLE + START -> RUNNING
IDLE + FAULT -> FAULT
RUNNING + STOP -> IDLE
RUNNING + FAULT -> FAULT
FAULT + RESET -> IDLE
Anything else -> MOTOR_ERROR_INVALID_TRANSITION
NULL motor -> MOTOR_ERROR_NULL
```

Used `switch` statements to implement the finite transition logic.

## 13. Pointer-Level Debugging

Diagnosed a `MotorController **` versus `MotorController *` compiler error.

Reinforced:

```text
motor  = MotorController *
*motor = MotorController
&motor = MotorController **
```

For:

```c
MotorController motor;
```

use:

```c
motor.state

```

For:

```c
MotorController *motor;
```

use:

```c
motor->state
motor_handle_event(motor, EVENT_START);
```

Decided to use a normal stack-allocated `MotorController` for the current practice.

## 14. `NULL` vs Enum States

Learned why:

```c
motor.state = NULL;
```

is conceptually incorrect.

`MotorState` represents the condition of an existing motor object, while `NULL` represents the absence of a valid object through a pointer.

```text
motor == NULL
    -> pointer validity

motor->state == MOTOR_FAULT
    -> condition of a valid object
```

If an unknown state is required, it should be explicitly represented with something such as `MOTOR_STATE_UNKNOWN`.
